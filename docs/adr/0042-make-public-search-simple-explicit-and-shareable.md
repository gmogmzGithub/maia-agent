# Make public search simple, explicit, and shareable

Catalog search begins with operation, zone, and property type and returns results
immediately. Price remains a primary refinement; additional filters are progressive
and property-type-specific. Customers may instead describe their need to Maia,
which confirms ambiguities and compiles the same authoritative catalog criteria.

Results are card-first with an optional map based only on Public Location. Cards
show a cover, short name, location, operation, visible price or consultation
message, a small set of applicable characteristics, and the save action. Results
load in bounded groups through `Mostrar más`, preserving filters and navigation
state. Dynamic searches are shareable but non-indexable by default; only curated
landing pages with distinct local value become indexable.

Organic `Más relevantes` ordering uses explicit criteria, current authority and
availability, and freshness. Alternative price and recency sorts are available.
Paid placement is always labeled `Patrocinada` and remains a separate commercial
concept. The catalog does not silently personalize from passive behavior or infer
wealth, age, or intent.

When the same physical Property is confirmed across source Listings, search shows
one result and prefers the Organization Listing without erasing source truth. Zero
results preserve the chosen criteria and offer explicit relaxation or a Maia
search for additional authorized inventory; neither Product nor Maia silently
broadens constraints.

The MVP does not add Saved Searches. Confirmed Property Needs and consented
reactivation already own new-match follow-up. Shared search URLs contain only
non-sensitive filters and always resolve current availability.
